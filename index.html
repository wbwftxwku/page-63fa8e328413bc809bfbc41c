01 / 演变编年

从纯粹的个人试验，到支持持续协作的分布式分流骨架。

2011 · 最初的契机

屏幕背后的共识与分散的坐标

当数个不同背景的协作者试图在同一张数字画布上工作时，跨地域网络所带来的断续感让交流变得极为昂贵。我们并未选用市面上庞杂的企业方案，而是通过几组轻量代理脚本，构建起属于少数人的私域中继。那是超平和Busters最初的形态。

2017 · 规则的重构

告别全局转发，走向精细分流

无差别的全流量包裹不仅是对带宽资源的浪费，更会导致本地服务与外部请求的频繁冲突。我们重新梳理了路由解析逻辑，将域名规则切分为直连、解析代理与专用通道三层结构，让网络行为重回各自本该行走的轨道。

2021 · 专线与拓扑演进

在震荡中寻找基准可用性

公网链路的日常抖动是不可避免的物理事实。我们引入了确定性更高的骨干传输节点与点对点冗余路径，在不夸大“加速”概念的前提下，将意外中断率压制在极低水平，为长时间保持连接的团队提供了基本的心理预期。

当下 · 秩序的维持

超平和Busters 的配置常态

如今这一套体系已被压缩进严整的订阅文档与清晰的分级配置中。没有冗余的后台劫持，没有华而不实的客户端噱头，它只是作为一套透明的传输工具，安静地在操作系统底层完成它的本职。

02 / 架构原则

我们如何平衡传输损耗、节点冗余与终端兼容性。

规则优先于蛮力

我们拒绝把所有数据无脑塞进单条通道。通过本地策略分流，确保局域网、内陆服务以原生速度响应，仅将受限请求定向至边界节点，大幅减少无谓的跃点延迟。

状态清晰可追溯

所有节点池的健康状况与带宽分配均遵循透明的负载调度逻辑，避免单一入口拥塞。使用者可以精确知晓当前的链路归属，排查故障不再是黑盒盲猜。

客户端中立立场

超平和Busters 不捆绑任何私有封闭软件。我们支持通用标准协议，使用者可在 macOS、Windows、iOS、Android 与 Linux 之间自由选择开源且受信任的核心工具。

04 / 终端协同指南

基于通用协议的接入逻辑，保障跨平台工作流的连贯。

多环境配置流程

超平和Busters 并不分发定制或修改版的私有安装包。为保障安全与透明，推荐使用者在各自操作系统内选用广泛经受审计的开源网络核心（如 Clash、Sing-box、Surge 或 Shadowrocket），并遵循以下四个步骤导入配置：

  1. 获取标准订阅接口：在账户面板中复制与当前客户端类型相符的配置链接，请勿在公共剪贴板或未经加密的即时通讯窗口传递该串字符。
  2. 拉取远程节点拓扑：在对应软件中选择“从 URL 下载配置”，软件将自动解析组策略、节点集群以及对应的 DNS 预判规则。
  3. 选定分流策略组：建议日常保持在“规则（Rule）”或“自动回落（Fallback）”模式下，让基础网络流量与边界访问流量由预设清单自主分配。
  4. 排查与缓存刷新：若切换网络后遇到解析停滞，建议重启系统网络适配器或重载配置文件，清除陈旧的本地 DNS 记录。

05 / 常见释疑

关于带宽调度、设备复用以及故障界定的客观回应。

如何界定不同计划中的设备同时在线限制？

在线设备数由服务端根据活跃连接的源 IP 地址及握手特征进行动态比对。同一局域网经由软路由等网关统一出站通常视作单一出口，但在多网络环境下漫游时，每一台独立建立隧道连接的终端均会占用配额。超出配额将引发新连接的自动排队或拒绝。

年付方案相较于月付，仅是价格优惠还是存在质量差异？

各等级套餐中包含的线路等级与节点池划分完全以计划名称为准，并不因计费周期的长短而区别对待。年付相当于以预付形式换取了两个月的费用减免（例如基础版 ¥150/年 即节省 ¥30），所有路由调度规则与带宽优先级保持一致。

原生流媒体解锁是如何实现的？是否保证永久有效？

原生解锁依赖于我们在特定地区部署的原生住宅或本地商用 IP 资源。流媒体平台的封控策略动态多变，因此我们通过自动化探针持续监测连通度并在后台调度备用出口。我们尽量维持高连通率，但任何声称绝对无死角或永不失效的承诺均不符合公网客观规律。

出现偶尔的连接停顿，该如何确认问题出在哪一侧？

首先建议使用系统命令行工具 ping 或 traceroute 诊断本地到默认网关的连通性；随后核验客户端规则中是否将目标域名误判为直连或黑洞；最后尝试切换节点池中的不同地理入口。若多组节点均呈现同一超时现象，通常为区域性骨干网波动。
